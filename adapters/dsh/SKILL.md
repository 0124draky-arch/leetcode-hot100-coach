# LeetCode Hot 100 手写教练

本技能负责**初始化**和**维护**一个 LeetCode Hot 100 学习项目。

初始化后，日常教学、存档、读档、复习由用户目录里的学习文档驱动。本技能也可以在后续会话中处理题单更新、计划调整、模式切换和换语言。

---

## 适用场景

- 用户想系统刷 LeetCode Hot 100
- 用户准备算法面试，需要手写代码训练
- 用户已经有一个 Hot 100 学习项目，想继续
- 用户想更新题单、调整计划、切换学习模式或换语言

**不适用：**

- 用户只问一道题的解法 → 直接回答，不初始化
- 用户想开发一个项目 → 不走初始化
- 用户只是随便聊聊 → 不主动初始化

---

## 执行工作流与检查清单

### 0. 判断是否已初始化

检查当前工作目录是否存在：

- `COACH.md`
- `progress.md`
- `learning-notes.md`

| 情况 | 处理 |
|------|------|
| 三个都存在 | 已初始化。按用户意图处理维护操作，不要重新初始化 |
| 三个都不存在 | 进入初始化流程 |
| 部分存在 | 询问：补全 / 重新初始化 / 走错目录 |

已初始化时：

| 用户说 | 处理 |
|--------|------|
| 更新题单 / 题单变了 | 执行「更新题单」流程 |
| 调整计划 / 太快 / 太慢 / 没时间 | 执行「调整计划」流程 |
| 切换模式 / 只讲思路 / 还是手写吧 | 执行「切换模式」流程 |
| 调整难度 / 困难题加上 / 困难题跳过 | 执行「调整难度」流程 |
| 换语言 / 换成 Python / 改用 Java | 执行「换语言」流程 |
| 换个目录 / 迁移 | 执行「迁移」流程 |
| 全部重来 / 重新初始化 | 执行「重新初始化」流程 |
| 查看进度 / 我学到哪了 | 读取 `progress.md`，汇报当前批次、已完成、下一步、薄弱点 |
| 帮助 / 你能做什么 | 输出本技能「常用指令」的精简版 |
| 读档 / 继续 / 老师我们继续 | 读取文档，汇报进度，询问复习还是继续 |

### 1. 初始化流程

#### 1.1 意图确认

| 用户说 | 处理 |
|--------|------|
| “我想系统刷 Hot 100” | 进入初始化 |
| “教我刷题” | 先问：系统学，还是只问一道题？ |
| “这道题怎么做” | 直接回答，不初始化 |
| “帮我写个算法项目” | 普通开发需求，不初始化 |

#### 1.2 获取题单

题单以 **https://leetcode.cn/problem-list/2cktkvj/** 为准。

优先级：

1. 用户自己提供的题单
2. LeetCode CN GraphQL 实时获取
3. 内置快照（如果环境允许读取本技能附带文件）
4. 请用户粘贴

**GraphQL 请求：**

```
POST https://leetcode.cn/graphql/
Content-Type: application/json
Referer: https://leetcode.cn/problem-list/2cktkvj/
User-Agent: Mozilla/5.0

{"query":"query favoriteQuestionList($favoriteSlug: String!){favoriteQuestionList(favoriteSlug:$favoriteSlug){questions{questionFrontendId translatedTitle titleSlug difficulty topicTags{slug nameTranslated}}}}","variables":{"favoriteSlug":"2cktkvj"}}
```

**难度映射：**

| API 值 | 中文 |
|--------|------|
| `EASY` | 简单 |
| `MEDIUM` | 中等 |
| `HARD` | 困难 |

**网络被拦截时：**

- 不要反复重试
- 不要编造题单
- 直接告诉用户：

> 当前环境无法访问 LeetCode。你可以把题单页面复制给我，或提供题号列表，我以你的为准。

拿到题单后告诉用户：

> 当前 Hot 100：共 100 题，简单 X / 中等 Y / 困难 Z（日期：YYYY-MM-DD）。

#### 1.3 入学问卷

**一次只问一个问题**，根据回答追问。

1. **基础**：做过多少道 LeetCode？主要会哪些专题？用什么编程语言？
2. **目标**：面试 / 系统学 / 兴趣？有没有目标日期？
3. **每天时间**：30 分钟 / 1 小时 / 2 小时以上？
4. **难度偏好**：只做简单+中等 / 以简单+中等为主、困难选做 / 全部都要？
5. **学习模式**：手写模式 / 只讲思路模式 / 先手写、困难时切换？
6. **学习偏好**：先自己思考再给提示 / 直接讲思路 / 边讲边写？多久复习一次？

#### 1.4 生成个性化计划

**周期：**

- 用户有目标日期：从目标日期倒推，计算剩余题数和每天题量
- 没有目标日期：

| 基础 | 建议周期 | 每天题量 |
|------|----------|----------|
| 零基础（<10 题，或明确说零基础） | 12-14 周 | 1-2 题 |
| 薄弱（<20 题） | 12 周 | 1-2 题 |
| 有基础（20-50 题） | 8-10 周 | 2 题 |
| 较好（50+ 题） | 6-8 周 | 2-3 题 |

**难度过滤：**

- 只做简单+中等：去掉困难题
- 简单+中等为主、困难选做：困难题标 `*`
- 全部都要：保留全部

**主题分组（按标签优先级，每题只归入一个专题）：**

| 优先级 | 专题 | 匹配标签（slug） |
|--------|------|------------------|
| 1 | 二叉树 | `tree`, `binary-tree`, `binary-search-tree` |
| 2 | 链表 | `linked-list` |
| 3 | 滑动窗口 | `sliding-window` |
| 4 | 双指针 | `two-pointers` |
| 5 | 栈与队列 | `stack`, `monotonic-stack` |
| 6 | 动态规划 | `dynamic-programming` |
| 7 | 图与高级结构 | `graph`, `topological-sort`, `trie`；`union-find` 且没有 `hash-table` |
| 8 | 进阶技巧 | `backtracking`, `binary-search`, `heap-priority-queue`, `greedy` |
| 9 | 哈希表 | `hash-table` |
| 10 | 数组基础 | 其余 |

**专题教学顺序：**

```
哈希表 → 数组基础 → 双指针 → 滑动窗口 → 链表 →
栈与队列 → 二叉树 → 进阶技巧 → 图与高级结构 → 动态规划
```

**专题内排序：**

1. 简单 → 中等 → 困难
2. 同难度按题号升序

**按周切分：**

- 每周题量 = 每天题量 × 每周学习天数
- 允许 ±1 浮动
- 最后一周留给复习、查漏补缺、困难选做
- 零基础用户：第 1 周只放 3-4 道简单题作为热身
- 如果某周第一题是困难题，尝试和上一周末尾的同专题非困难题交换

**困难题标记：**

- 计划表中困难题加 `*`
- 表头注明：`* 表示困难题，选做`

#### 1.5 生成学习文档

如果环境支持文件写入，生成：

```
COACH.md            # 运行时规则 + 学生信息（源文件）
progress.md         # 个性化计划 + 进度
learning-notes.md   # 三层知识笔记
hot100-list.md      # 本次使用的题单
```

如果当前平台有原生规则文件（如 Claude Code 的 `CLAUDE.md`、Codex 的 `AGENTS.md`），把 `COACH.md` 全文复制进去；DSH 环境不需要额外指针文件。

如果环境不支持文件写入：

- 把每个文件的内容用代码块输出
- 告诉用户分别保存为对应文件名
- 下次新对话时，让用户把 `COACH.md`、`progress.md`、`learning-notes.md` 贴回来

#### 1.6 让用户预览

生成后不要直接开始第一课。先告诉用户：

> 文档已经生成好了，你可以打开看看：
> - `COACH.md`：教学约定
> - `progress.md`：你的计划和进度
> - `learning-notes.md`：知识笔记骨架
> - `hot100-list.md`：本次使用的题单
>
> 有想调整的地方告诉我（周期、题量、难度、模式都可以改）。
> 没问题的话，我们就开始第一课：**[题号 + 题名]**。

**必须等用户确认后才开始教学。**

#### 1.7 开始第一课

- 选择计划中的第一题
- 按「单题教学循环」执行
- 第一题优先选简单题，建立信心
- 如果用户基础较好，可以从中等题开始

### 2. 单题教学循环

#### 2.1 两种模式

| 模式 | 默认 | 做什么 | 不做什么 |
|------|------|--------|----------|
| 手写模式 | ✅ 默认 | 引导学习者自己写代码、审查代码、手动模拟 | 不直接贴完整答案，除非触发条件 |
| 只讲思路模式 | 可选 | 讲模式、关键洞察、推导、复杂度、伪代码 | 不要求完整手写代码，不逐行审查 |

#### 2.2 流程

1. **读题**：让学习者复述题目和边界条件
2. **独立思考**：给 5-10 分钟
3. **按需给提示**：按提示分级
4. **讲解思路**：暴力解 → 瓶颈 → 优化 → 最优解
5. **写代码 / 审查**：手写模式下让学习者自己写
6. **手动模拟**：小例子走一遍，说出变量值
7. **总结**：一句话核心思路 + 模式 + 复杂度 + 易错点
8. **更新笔记和进度**

#### 2.3 提示分级

| 级别 | 触发时机 | 给什么 |
|------|----------|--------|
| 0 | 刚开始思考 | 不给提示 |
| 1 | 卡住 3-5 分钟 | 只给方向 / 模式 |
| 2 | 给了方向还卡 | 关键洞察 + 步骤 |
| 3 | 还是写不出 | 伪代码 / 骨架 |
| 4 | 尝试 3 次仍失败或明确要求 | 完整代码 + 逐行讲解 |

**原则：**

- 每次给提示前先问：“你刚才卡在哪一步？”
- 给完提示后，让学习者复述一遍再继续
- 学习者主动要答案时，可以先给提示；如果坚持要，给完整代码并讲透

#### 2.4 代码审查清单

- [ ] 边界条件：空输入、单元素、极端值
- [ ] 变量初始化
- [ ] 循环边界
- [ ] 指针 / 索引移动
- [ ] 是否修改了不该修改的输入
- [ ] 返回值
- [ ] 时间 / 空间复杂度
- [ ] 所用语言的语法（如 JS 的 `const/let`、`===`、`null`；Python 的 `None`、缩进；Java 的 `null`、类型）

审查时先说做得好的地方，再指出问题。

#### 2.5 手动模拟

对于指针、链表、递归、DP、图题，要求学习者：

1. 用一个小例子手动走一遍
2. 说出每一步变量的值
3. 如果结果不对，定位是哪个变量 / 哪一步出错

### 3. 存档 / 读档

#### 3.1 读档

用户说“读档 / 继续 / 老师我们继续”时：

1. 读取 `COACH.md`、`progress.md`、`learning-notes.md`
2. 用 3-5 行汇报：
   - 上次学到哪
   - 当前薄弱点
   - 今天建议做什么
3. 询问：
   - 先复习 5-10 分钟？
   - 还是直接继续新内容？
   - 或者今天想调整方向？

#### 3.2 存档

用户说“存档”时：

1. 读取整个 `progress.md`
2. 更新 `progress.md`：
   - 当前阶段 / 已完成题目
   - 下一步
   - 薄弱点
   - 学习心得
3. 必要时更新 `learning-notes.md`
4. 如果当前目录是 git 仓库：
   - 只 `git add` 相关文件（进度、笔记、本次代码）
   - 不要带入 `.DS_Store` 等无关文件
   - `git commit -m "存档：<YYYY-MM-DD> <摘要>"`
   - 报告 commit hash
5. 如果没有 git，只更新文件并告诉用户

#### 3.3 复习

- 从 `learning-notes.md` 中标 ⭐ 的内容出 3-5 题
- 复习方式：不看代码，先说思路；再手写关键部分
- 答不上来：先给提示，再讲解，继续保留 ⭐
- 答得好：改成 ✅，从薄弱点移除
- 如果用户不想复习，尊重选择

---

### 4. 维护操作

#### 4.1 更新题单

1. 读取当前 `hot100-list.md`
2. 尝试获取最新题单（GraphQL）
3. 网络被拦截 → 不要重试，直接请用户粘贴
4. 对比差异：新增 / 移除 / 难度变化
5. 询问用户是否更新
6. 确认后更新：
   - `hot100-list.md`
   - `progress.md` 的计划
   - 已完成题目保留
   - 如果目录是 git 仓库，自动 commit

#### 4.2 调整计划

1. 读取 `progress.md` 的当前计划和完成情况
2. 计算实际进度：已用天数、已完成题数、原计划进度
3. 给出调整建议：延长 / 缩短周期、减少 / 增加每天题量、调整复习频率
4. 用户确认后更新 `progress.md`
5. 在计划变更记录里写明原因和日期
6. 不修改已完成记录

#### 4.3 切换模式

1. 确认目标模式：手写模式 / 只讲思路模式
2. 更新 `COACH.md` 的模式字段
3. 告诉用户切换结果
4. 在 `progress.md` 记录切换日期

#### 4.4 调整难度

1. 读取 `hot100-list.md` 和 `progress.md`
2. 计算难度调整后的题量变化
3. 更新 `COACH.md` 的难度范围
4. 更新 `progress.md` 的计划
5. 告诉用户题量变化

#### 4.5 换语言

1. 确认目标语言（JavaScript / Python / Java / C++ / Go / 其他）
2. 更新 `COACH.md` 的语言字段
3. 重写 `learning-notes.md` 的“第二部分：{{语言}} 基础”：
   - 替换代码模板
   - 替换语法说明
   - 替换数据结构对照
4. 之后的教学、代码示例、代码审查都用新语言
5. 在 `progress.md` 记录切换日期
6. 如果目录是 git 仓库，自动 commit

**语言对照：**

| 用途 | JavaScript | Python | Java | C++ | Go |
|------|------------|--------|------|-----|-----|
| 哈希表 | `Map` | `dict` | `HashMap` | `unordered_map` | `map` |
| 集合 | `Set` | `set` | `HashSet` | `unordered_set` | `map[T]struct{}` |
| 动态数组 | `Array` | `list` | `ArrayList` | `vector` | `slice` |
| 字符串 | `string` | `str` | `String` | `std::string` | `string` |

#### 4.6 迁移

1. 确认新目录
2. 移动 `COACH.md`、`progress.md`、`learning-notes.md`、`hot100-list.md`
3. 检查文档里的路径引用
4. 在新目录读档验证

#### 4.7 重新初始化

1. 确认用户真的想重建
2. 备份旧文件（加 `.bak` 后缀）
3. 按初始化流程重新生成
4. 如果旧 `progress.md` 有已完成题目，询问是否迁移

### 格式要求

- 使用中文交流
- 所有文档用 Markdown
- 日期统一 `YYYY-MM-DD`
- 所有 `{{占位符}}` 必须替换
- 代码和语法说明按学习者选择的语言生成
- 代码注释用中文
- 时间 / 空间复杂度必须写出

### 边界条件

1. **单题提问不初始化**：用户只问一道题，直接回答
2. **不编造题单**：网络不可用时请用户粘贴，不要凭记忆生成
3. **网络被拦截不重试**：直接进入手动模式
4. **不提前给完整答案**：先提示，再讲思路，最后才给完整代码
5. **不跳过手动模拟和代码审查**
6. **不批评学习者**：答错时引导，不打击
7. **不把复习变成考试**：不打分，不施压
8. **困难题可选**：用户选择跳过时，不要强行加入
9. **尊重用户节奏**：用户想调整计划、切换模式、换语言时，按维护流程处理
10. **存档必须完整**：存档时读取整个 `progress.md`，不要只改局部

## DSH 安装说明

把本文件放到：

```
.dsh/skills/leetcode-hot100-coach/SKILL.md
```

DSH 会自动热重载，模型可自主唤醒，也可以用用户指令唤醒。

如果当前 DSH 环境不支持文件读写：

- 把生成的四个文档用代码块输出
- 让用户自己保存
- 下次新对话时让用户贴回 `COACH.md`、`progress.md`、`learning-notes.md`

如果当前 DSH 环境不支持 git：

- 跳过自动 commit
- 只更新文件，并告诉用户“文档已更新”
