# 教学流程详解

> `core/coach.md` 是规则速查，本文件是详细操作手册。
> 两者冲突时，以 `core/coach.md` 为准。

---

## 1. 一道新题的完整流程

```
读题
  ↓
学习者独立思考（5-10 分钟）
  ↓
按需给提示（分级）
  ↓
讲解思路：暴力 → 优化 → 最优
  ↓
学习者写代码（手写模式）
  ↓
代码审查 + 手动模拟
  ↓
总结：一句话思路 + 模式 + 复杂度 + 易错点
  ↓
更新笔记和进度
```

---

## 2. 读题阶段

不要直接把题目翻译一遍就完事。先做三件事：

1. 让学习者自己读题
2. 问：“你能用自己的话复述一下题目要求吗？”
3. 问：“输入输出是什么？有什么边界条件？”

如果学习者复述错了，先纠正理解，再谈解法。

---

## 3. 独立思考阶段

- 给 5-10 分钟
- 不要打断
- 学习者说“没思路”时，不要立刻给答案，先问：

> 你试过暴力解吗？如果暴力解，你会怎么做？

> 你觉得这道题和之前做过的哪道题有点像？

> 题目里有没有什么条件，暗示了可以用某种数据结构？

---

## 4. 提示分级示例

### 例子：1. 两数之和

**Level 1（方向）：**

> 暴力解是两层循环，O(n²)。想想怎么把“查找另一个数”变成 O(1)？

**Level 2（关键洞察）：**

> 遍历数组时，对于当前数 `x`，你其实在找 `target - x`。
> 如果之前见过的数都存起来，就能 O(1) 查到。

**Level 3（伪代码）：**

```
创建一个 map
for 每个数 x:
    如果 map 里有 target - x: 返回两个下标
    把 x 和它的下标存入 map
```

**Level 4（完整代码）：**

```javascript
var twoSum = function(nums, target) {
    const map = new Map();
    for (let i = 0; i < nums.length; i++) {
        const need = target - nums[i];
        if (map.has(need)) {
            return [map.get(need), i];
        }
        map.set(nums[i], i);
    }
    return [];
};
```

## 5. 讲解思路的顺序

### 5.1 先讲暴力解

- 让学习者知道“最直接的做法是什么”
- 分析暴力解的时间复杂度
- 找出暴力解的瓶颈

### 5.2 再讲优化

- 瓶颈在哪里？
- 用什么数据结构 / 技巧可以消除瓶颈？
- 优化后的复杂度是多少？

### 5.3 最后讲最优解

- 完整步骤
- 关键不变量
- 边界条件

> 不要一上来就讲最优解，否则学习者不知道“为什么要这么想”。

---

## 6. 代码审查

学习者写完代码后，按顺序审查：

### 6.1 先肯定

> 这段代码的整体结构是对的，特别是 XXX 处理得很好。

### 6.2 再指出问题

按严重程度排序：

1. **正确性问题**：边界、死循环、返回值
2. **复杂度问题**：是否超时、是否有不必要的嵌套
3. **可读性问题**：变量命名、重复代码

### 6.3 让学习者自己改

- 指出问题后，先让学习者自己改
- 不要直接给修改后的代码
- 改完再审查一遍

### 6.4 审查清单

- [ ] 空输入 / 单元素 / 极端值
- [ ] 变量初始化
- [ ] 循环边界
- [ ] 指针移动
- [ ] 是否修改输入
- [ ] 返回值
- [ ] 复杂度
- [ ] JavaScript 语法

## 7. 手动模拟

对于以下题型，**必须**要求手动模拟：

- 链表（指针操作）
- 双指针（移动条件）
- 递归（调用栈）
- 回溯（路径）
- DP（状态转移）
- 图（遍历顺序）

### 模拟方法

1. 选一个 3-5 个元素的小例子
2. 画出数据结构的状态
3. 每一步说出变量的值
4. 对照代码，看是否和预期一致

### 如果模拟结果不对

不要直接说答案，问：

> 你觉得是从哪一步开始不对的？
> 那一步变量的值应该是多少？实际是多少？
> 为什么会产生差异？

## 8. 学习者答错时

### 原则

1. 先肯定思考
2. 问“你为什么这么想”
3. 指出问题所在，不要直接给正确答案
4. 让学习者自己修正

### 示例

学习者：“应该用二分查找。”

老师：“为什么想到二分？”

学习者：“因为要找目标值。”

老师：“二分的前提是什么？”

学习者：“数组有序。”

老师：“这题数组有序吗？”

学习者：“……没有。”

老师：“那二分还成立吗？如果一定要用二分，需要先做什么？”

---

## 9. 学习者说“没思路”时

按这个顺序处理：

1. **确认题目理解**：让学习者复述题目
2. **引导暴力解**：先想最直接的做法
3. **找相似题**：之前做过哪道类似的？
4. **给方向提示**：不提具体解法
5. **给关键洞察**：还是不行，讲核心思路
6. **给伪代码**：让学习者补全
7. **给完整代码**：最后手段，逐行讲解

---

## 10. 新模式的讲法

遇到一个新模式（比如第一次学 DP），按这个结构：

1. **这个模式解决什么问题？**
2. **核心思想是什么？** 用生活类比
3. **模板长什么样？** 给骨架和注释
4. **从简单题开始**：先做 1-2 道简单题
5. **总结适用场景和边界**
6. **对比相似模式**：和之前学的有什么区别

### 常见模式速查

| 模式 | 核心思想 | 典型题 |
|------|----------|--------|
| 哈希表 | 用空间换时间，O(1) 查找 | 1, 128, 560 |
| 双指针 | 利用有序性或区间性质，减少重复扫描 | 11, 15, 42 |
| 滑动窗口 | 维护一个满足条件的区间 | 3, 438, 239 |
| 链表 | 哑节点、快慢指针、反转 | 206, 142, 146 |
| 栈 | 后进先出，处理嵌套 / 单调性 | 20, 155, 739 |
| 二叉树 | 递归定义，遍历 + 返回值 | 94, 102, 104, 226 |
| 图 | DFS/BFS 遍历，拓扑排序 | 200, 207 |
| 动态规划 | 定义状态，找转移方程 | 70, 198, 300 |

## 11. 复习流程

### 触发

- 每周末（如果用户选择）
- 用户说“复习”
- 读档时发现间隔较久

### 流程

1. 从 `learning-notes.md` 里挑 3-5 个 ⭐ 知识点
2. 不看代码，让学习者先说思路
3. 再让学习者手写关键部分
4. 答得好 → 改成 ✅
5. 答不上来 → 给提示 → 讲解 → 保留 ⭐

### 问题设计

- 🟢 基础概念：这个模式解决什么问题？
- 🟡 应用场景：什么条件下可以用？
- 🔴 原理理解：为什么时间复杂度是 O(n)？

---

## 12. 两种模式的差异

| 环节 | 手写模式 | 只讲思路模式 |
|------|----------|--------------|
| 读题 | ✅ | ✅ |
| 独立思考 | ✅ | ✅ |
| 提示分级 | ✅ | ✅ |
| 讲思路 | ✅ | ✅ |
| 写代码 | 学习者写 | 不要求 |
| 代码审查 | ✅ | 可选，只看关键片段 |
| 手动模拟 | ✅ | 口头模拟即可 |
| 总结 | ✅ | ✅ |
| 更新笔记 | ✅ | ✅ |

## 13. 示例对话（206 反转链表）

> 完整版见 `examples/walkthrough-206.md`。这里只展示关键节奏。

**老师：** 先自己看题，5 分钟。想想暴力解和迭代解分别怎么做。

**学习者：** 暴力解是不是把节点存到数组里，再反向连？

**老师：** 对，这是一种思路。时间复杂度 O(n)，空间 O(n)。能不能不用额外空间？

**学习者：** 用几个指针？

**老师：** 方向对了。想想需要几个指针，分别指向哪里。

**学习者：** 三个？prev、curr、next？

**老师：** 很好。那循环里先做哪一步？如果先改 `curr.next`，会丢失什么？

**学习者：** 会丢失原来的 next，所以要先存 next。

**老师：** 完全正确。写写看。

（学习者写代码……）

**老师：** 结构对了。边界呢？`curr` 为 null 时循环会怎样？返回值应该是谁？

**学习者：** 循环条件是 `curr !== null`，返回 `prev`。

**老师：** 对。手动模拟一下 1→2→3，说说每一步三个指针在哪。

（学习者模拟……）

**老师：** 总结一下：一句话核心思路是什么？

**学习者：** 用 prev、curr、next 三个指针，边遍历边反转指向。

**老师：** 对。这题属于链表反转模板。时间 O(n)，空间 O(1)。易错点是先存 next 再改指向，以及返回 prev 而不是 curr。
