# 更新与调整

> 初始化只做一次。日常的题单更新、计划调整、模式切换，不需要重跑初始化。

---

## 1. 更新题单

**触发：** 用户说“更新题单”“题单变了”“检查一下最新 Hot 100”。

**流程：**

1. 按 `core/problem-list.md` 重新获取题单
2. 读取当前 `hot100-list.md`
3. 对比差异：
   - 新增题目
   - 移除题目
   - 难度变化
4. 向用户展示差异
5. 询问是否更新
6. 用户确认后：
   - 更新 `hot100-list.md`
   - 调整 `progress.md` 的计划
   - 已完成题目保留
   - 如果目录是 git 仓库，自动 commit：`更新题单：<YYYY-MM-DD>`

**网络被拦截时：**

- 不要反复重试
- 直接请用户粘贴题单或题号列表
- 以用户提供的列表为准，不要编造

**不要直接替换题单，必须让用户确认。**

---

## 2. 调整计划

**触发：** 用户说“太快了”“太慢了”“每天没那么多时间”“想加量”。

**流程：**

1. 读取 `progress.md` 的当前计划和完成情况
2. 计算实际进度：
   - 已用天数
   - 已完成题数
   - 原计划进度
3. 给出调整建议：
   - 延长 / 缩短周期
   - 减少 / 增加每天题量
   - 调整复习频率
4. 用户确认后：
   - 更新 `progress.md`
   - 在计划变更记录里写明原因和日期
   - 不修改已完成记录
   - 如果计划摘要变了，更新 `COACH.md` 并同步原生文件（见第 8 节）

---

## 3. 切换模式

**触发：** 用户说“切换成只讲思路模式”“还是让我手写吧”。

**流程：**

1. 确认目标模式：
   - 手写模式
   - 只讲思路模式
2. 更新 `COACH.md` 的模式字段
3. 告诉用户：

> 已切换到只讲思路模式。之后我会重点讲模式、洞察和复杂度，不要求你完整手写；关键片段还是会给你看。

4. 在 `progress.md` 里记录切换日期
5. 更新 `COACH.md` 并同步原生文件（见第 8 节）

---

## 4. 调整难度范围

**触发：** 用户说“困难题也加上”“困难题先跳过”。

**流程：**

1. 读取 `hot100-list.md` 和 `progress.md`
2. 计算难度调整后的题量变化
3. 更新 `COACH.md` 的难度范围
4. 更新 `progress.md` 的计划
5. 告诉用户题量变化
6. 更新 `COACH.md` 并同步原生文件（见第 8 节）

---

## 5. 换语言

**触发：** 用户说“换成 Python”“我想用 Java”“换语言”。

**流程：**

1. 确认目标语言（JavaScript / Python / Java / C++ / Go / 其他）
2. 更新 `COACH.md` 的“编程语言”字段
3. 重写 `learning-notes.md` 的“第二部分：{{语言}} 基础”：
   - 替换代码模板
   - 替换语法说明
   - 替换数据结构对照（如 `Map` → `dict`、`Set` → `set`）
4. 告诉用户：

> 已切换到 Python。之后代码示例、代码审查和笔记都会用 Python。
> 之前的已完成记录不受影响。

5. 在 `progress.md` 记录切换日期
6. 更新 `COACH.md` 并同步原生文件（见第 8 节）
7. 如果目录是 git 仓库，自动 commit：`换语言：<旧语言> → <新语言>`

**注意：**

- 不要删除旧的题目笔记；只改语言相关的模板和语法说明
- 如果用户只是想看某道题的另一种语言写法，不需要切换全局语言

---

## 6. 换目录 / 迁移

**触发：** 用户想把学习文档移动到新目录。

**流程：**

1. 确认新目录
2. 移动：
   - `COACH.md`
   - `progress.md`
   - `learning-notes.md`
   - `hot100-list.md`
   - 平台原生文件
3. 检查文档里的路径引用是否需要更新
4. 如果路径变了，更新 `COACH.md` 并同步原生文件（见第 8 节）
5. 在新目录读档验证

---

## 7. 重新初始化

**什么时候需要：**

- 想换一个全新的学习项目
- 想彻底重新制定计划（不是微调）
- 文档损坏，无法恢复

**流程：**

1. 确认用户真的想重建
2. 备份旧文件（例如加 `.bak` 后缀）
3. 按 `core/onboarding.md` 重新初始化
4. 如果旧 `progress.md` 有已完成的题目，询问是否迁移
5. 迁移时保留完成记录和学习心得

> 重新初始化是例外，不要因为用户说“更新题单”就重建所有文档。

---

## 8. 同步原生文件

当 `COACH.md` 发生变化时，必须同步平台原生文件：

| 平台 | 原生文件 |
|------|----------|
| Claude Code | `CLAUDE.md` |
| Codex | `AGENTS.md` |
| Cursor | `.cursorrules` |

同步方式：

1. 重新读取 `COACH.md`
2. 在头部加上生成说明（`本文件由 COACH.md 生成，请优先修改 COACH.md`）
3. 覆盖对应的原生文件
4. 不要手动修改原生文件；它是生成物

什么时候需要同步：

- 切换模式
- 调整难度
- 调整计划摘要
- 换语言
- 修改学生信息
- 迁移目录

> `progress.md` 和 `learning-notes.md` 不需要同步到原生文件；它们由 AI 每次读取。

## 9. 常见问题

| 用户说 | 处理 |
|--------|------|
| “题单好像变了” | 更新题单流程 |
| “我没时间了” | 调整计划（降低题量 / 延长周期） |
| “今天不想写代码” | 临时切换到只讲思路模式（不一定要改 COACH.md，可以只本次） |
| “我想先学 DP” | 调整计划顺序，不修改题单 |
| “这道题忘了” | 回炉复习，不重新初始化 |
| “换个新目录” | 迁移流程 |
| “全部重来” | 重新初始化（先备份） |
